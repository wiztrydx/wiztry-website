ダウンロードのフォルダに、メモのファイルが1つ置かれていた。それだけでAIエージェント（頼んだ作業を自分で進めるAI）が乗っ取られかけた。2026年10月に、セキュリティ会社が公表した件です。

実際に狙われたのは、OpenAI の Codex でした。ただ、同じことは Claude Code（Anthropic のAIエージェント）でも他人事ではありません。なので先に知って、設定で止めておきましょう。

この記事は、11月10日に公開した YouTube 動画の内容を、記録と公式の情報に照らして書き直したものです。難しい言葉は、会社の備品にたとえて説明します。

## この記事の要点

- AIへのお願いは「張り紙」、設定は「鍵」です。だまされた時に止まるのは、鍵の方です
- ダウンロードのフォルダでは起動しません。その外に仕事ごとのフォルダを作り、使う資料だけを移します
- パスワードをチャットやコマンド（パソコンへの命令文）に書きません。許可した内容は、たまに見直します
- サンドボックス（AIの命令が動ける範囲を区切る囲い）と読み取り禁止を組み合わせます。これだけで全部は防げないので、最新版にしておくことも土台です

## まず全体像：3つの手口と、防ぎ方

| 手口 | 会社でたとえると | 今日の一手 |
|---|---|---|
| 外から来たファイルの指示に従う | 郵便受けに入っていた偽の指示書に従う | ダウンロードの外に、仕事用のフォルダを作る |
| パスワードが設定に残ることがある | 申請書に金庫の番号を書いたまま保管する | 許可を見直し、番号は別に預ける |
| AIが作ったプログラムが罠を踏む | 届いた箱の偽物の部品を使ってしまう | 囲いの中で動かす |

## お願いは張り紙、設定は鍵

Claude Code の守り方は、大きく2つに分かれます。

1. AIへのお願い：CLAUDE.md や頼む文に「これはしないで」と書く
2. 仕組みで止める：設定ファイルやサンドボックスで、Claude Code の側で止める

CLAUDE.md は、作業のルールを書いてフォルダに置くメモです。会社でいえば、壁の張り紙です。ふだんは守ってくれますが、別の指示にだまされると素通りします。

設定は鍵です。公式ドキュメントにも、許可のルールを守らせるのはAIではなく Claude Code だと書かれています。今回の3つの手口は、どれも張り紙だけでは防げません。

![お願いは張り紙、設定は鍵。張り紙はだまされると素通り。鍵は見せない場所を決め、囲いは動ける範囲を区切る](/blog/claude-code-security-settei/02-sign-key.webp)

ここで1つクイズです。Claude Code が命令を動かす前に出す許可の画面で、「許可」は何%押されていると思いますか。

答えは約93%です（Anthropic の計測。攻撃が成功する割合ではありません）。慣れてくると、中身を読まずに押してしまうんですよね。正直なところ、私もよくやってしまいます。なので、人の注意力だけに頼らず、仕組みで止めます。

## 手口1：外から来たファイルの指示に従ってしまう

### 何が起きるのか

Claude Code は、起動したフォルダと、その上の階層にある CLAUDE.md を作業のルールとして読みます。一方、ホームページの中には、クリックしなくてもダウンロードのフォルダへファイルを保存できるものがあります。

つまりダウンロードのフォルダは、外の人も物を入れられる郵便受けです。そこでAIを起動すると、紛れ込んだ紙を社内の指示書だと思ってしまうことがあります。

冒頭の件では、Codex が読むルールのファイル（AGENTS.md）が、いつの間にか置かれていました。Codex はその指示で悪いプログラムを入れようとしましたが、見つけたセキュリティ会社 Forever Security が止めています。誰がどう置いたのかは、分かっていません。

同じ会社が Claude Code で検証すると、検証用に作った文面では、約半分の回で通信先の設定を書き換えたそうです。同社は、この書き換えには人の承認が要るとも書いています。承認した条件での数字か、何回試したかは書かれていません。ふだんの利用で起きる確率ではありません。

### 実演：「こんにちは」とだけ送ったのに

動画では、練習用のフォルダに、害のない1行だけの CLAUDE.md を置きました。そこで「こんにちは」とだけ送ると、返事の最初が、そのファイルに書いたとおりの文になりました。

![実演の画面。こんにちはとだけ送ったのに、返事の最初がフォルダに置いた害のないファイルの指示どおりになった](/blog/claude-code-security-settei/03-demo-claude-md.webp)

もしこれが悪い指示だったら、と考えると、防ぎ方ははっきりします。

### 今日の一手：仕事ごとにフォルダを作る

1. ダウンロードのフォルダでは起動しない。デスクトップアプリで作業するフォルダに選ぶのも同じです
2. 仕事ごとのフォルダを、ダウンロードの外に作る。見積の資料なら、書類の中に「見積」のフォルダです。ダウンロードの中に作ると、ダウンロードにある CLAUDE.md も読まれます
3. 使うファイルだけを移して、そこで起動する
4. もらったフォルダに CLAUDE.md や AGENTS.md があったら、起動する前に中身を読む。隠しフォルダの `.claude` の中も見ます

## 手口2：「今後は許可を求めない」でパスワードが残ることがある

### 何が起きるのか

許可の画面には「今後は許可を求めない」（英語では Yes, and don't ask again）のボタンがあります。押すと、その命令文が設定ファイルに保存され、次からは聞かずに動きます。

すごく便利なボタンです。ただ、命令文にパスワードやAPIキー（外部のサービスを使うための合鍵）が入っていると、それも読める文字のまま残ることがあります。

動画を公開したあとの11月12日付の更新で、秘密の値に見える物が入った許可は保存されず、起動している間だけ有効になりました。ただし、秘密に見える物が対象なので、すべてを見分けられるとは限りません。更新の前に保存された分も、あとの棚卸しで確かめます。

保存先のファイル（settings.local.json）は、Claude Code が作った物なら、Git（ファイルの変更を記録する仕組み）に載らないよう自動で外されます。ただし自分で作った物は外れませんし、フォルダごと人に渡せば中身も渡ります。GitHub（プログラムをネットで共有する場所）に公開されれば、合鍵も公開されます。他人に使われた分の請求は、自分の会社に来てしまいます。

報道によると、セキュリティ会社 Apiiro が GitHub に公開されていた、この保存先のファイル約10万件を調べたところ、1,122件に本物のパスワードやキーがありました（今も使えるかまでは確かめていない数字です）。

### 実演：ダミーのパスワードが、そのまま残った

動画では（この更新の前です）、ダミーのパスワードが入った命令で、あえてボタンを押しました。保存されたファイルを開くと、ダミーのパスワードがそのまま入っていました。

### 今日の一手：棚卸しと、合鍵の預け方

まず、許可の棚卸しです。ターミナル版（文字で操作する画面の Claude Code）で `/permissions` と打つと、一覧が出ます。デスクトップアプリでは、このコマンドの画面は使えません。

1. Allow（許可）の欄で、パスワードや「sk-」で始まる長い英数字が入った物を先に探す
2. 本物が入っていたら、消す前にどのサービスのキーかだけを控え（値は写さない）、発行元の画面で作り直す。一度 GitHub に載せた物は、ファイルを消しても履歴に残ります
3. そのあと、Allow の欄から、その許可と覚えのない物を消す。必要な時はもう一度確認（画面か、設定によってはAIの判定）に回るので、迷ったら消して大丈夫です。Deny（禁止）の欄は消しません

次に、合鍵の預け方です。環境変数（パソコンに名前を付けて値を預ける仕組み）を使うと、命令文には名前だけが残ります。ただし、隠す金庫ではありません。Claude が動かす命令やプログラムからは読めます。保存される文に値を残さないための方法です。

預ける作業は、AIに頼まず自分でします。キーをチャットに貼って「預けて」と頼むと、同じ問題が起きるからです。分からなければ、キーは貼らずに手順だけをAIに聞いてください。

## 手口3：AIが作ったプログラムが罠を踏む

### 何が起きるのか

2026年8月に、研究者の Johann Rehberger 氏が検証を公開しました。罠を仕込んだホームページの要約を Claude Code に頼むと、パソコンの中で悪いプログラムが動いた、というものです。許可の判断をAIに任せる使い方で、少ない回数を試した検証です。毎回起きたわけではありません。

ポイントは、Claude が怪しいプログラムを自分で開いたのではないことです。怪しい物は避けて、安全のつもりで自分のプログラムを作りました。そのプログラムが、一緒に届いていた偽物の部品を読み込んでしまいました。

ふだんの仕事でも、似た形は起き得ます。ネットから取ったフォルダで「テストを動かして」「必要な部品を入れて」と頼む。配布されているスキル（AIへの手順書）や ZIP ファイルを「動かしてみて」と頼む。この2つは、特に注意してください。

![AIが作ったプログラムも囲いの中へ。囲いなしでは秘密のファイルも読める。囲いと読み取り禁止があれば、禁止したファイルは読めない](/blog/claude-code-security-settei/07-program.webp)

### 今日の一手：サンドボックスで囲う

サンドボックスをオンにすると、Claude の命令と、そこから動くプログラムは、作業フォルダの外へ原則書き込めません。通信できる相手も制限されます。初期設定はオフです。

ターミナル版で `/sandbox` と打ち、画面で選びます。オンになるのは、今開いているフォルダだけです。パソコンによって、使える条件が違います。

| パソコン | サンドボックス |
|---|---|
| Mac | 追加の道具なしで使える |
| Windows の WSL2（Windows の中で Linux を動かす仕組み）・Linux | 追加の道具が要る |
| Windows そのまま | 使えない |

大事な点がもう1つあります。囲いの中でも、読むことはパソコンのほとんどの場所でできます。なので、見せたくないファイルは読み取り禁止にします。囲いと禁止は、2つで1組です。

動画の実演では、ダミーの鍵のファイルを読もうとしたプログラムが、開く所で止まりました。

![サンドボックスの実演。読み取り禁止にしたダミーの鍵のファイルを読むプログラムが、開く時点で拒否された。保存場所は伏せている](/blog/claude-code-security-settei/08-demo-sandbox.webp)

### コピーして試せる、最小の設定

動画の9分26秒ごろに映した設定から、実演用の行を除いた物です。練習用のフォルダの中に `.claude` というフォルダを作り、`settings.json` という名前で保存します。点で始まる名前は隠しフォルダなので、作れない・見えない時は担当の人に頼んでください。

```json
{
  "permissions": {
    "deny": [
      "Read(.env)",
      "Read(.env.*)"
    ]
  },
  "sandbox": {
    "enabled": true,
    "allowUnsandboxedCommands": false,
    "failIfUnavailable": true
  }
}
```

| 書いてあること | 意味 |
|---|---|
| deny の2行 | パスワードなどを書くことが多い「.env」という名前のファイルを読ませない |
| enabled | 囲いをオンにする |
| allowUnsandboxedCommands | 失敗した命令を、囲いの外でやり直させない |
| failIfUnavailable | 囲いを使えない時は起動しない |

使う前に、4つ確かめてください。

1. Windows そのままや、追加の道具が入っていない WSL2・Linux では、最後の行があると Claude Code が起動しません。その時は、保存した settings.json を別の場所へ移すと戻ります
2. すでに settings.json がある場合は、上書きせずに担当の人と中身を足します
3. 一部の命令が動かなくなることがあります。仕事のフォルダに入れる前に、練習用のフォルダで試します
4. 保存したら `/status` の Setting sources（読み込んだ設定の一覧）を見ます。ダミーの .env を置いて、読めないことも確かめます

この設定が効くのは、保存したフォルダで起動した時だけです。守られるのも、そのフォルダの中（下の階層を含む）にある、書いた名前のファイルだけです。よそのフォルダの物や、別の名前のファイルに書いたパスワードは守れません。

囲いが効くのも命令とプログラムで、外のサービスとの連携などは囲いの外で動きます。覚えのない通信の許可を聞かれたら、押さないでください。確認を全部飛ばす設定では聞かれずにつながり、AIの判定に任せる設定でも画面は出ません。

## 全部の土台は、最新版にしておくこと

古い版のままだと、直ったはずの穴が開いたままです。この秋（9〜10月）だけで、Claude Code とデスクトップアプリに重大度の高い問題が5件公表され、どれも更新で直っています。

さらに11月13日付の更新でも、読み取り禁止の一部が、フォルダを移動すると効かなくなる不具合が直りました。設定をした人ほど、更新が要るということです。

| 使い方 | 更新の仕方 |
|---|---|
| デスクトップアプリ（Mac） | メニューの Claude → Check for Updates |
| デスクトップアプリ（Windows） | メニューの Help → Check for Updates |
| ターミナル版（公式のインストーラー） | 自動で更新。版は `claude --version` で分かる |
| ターミナル版（Homebrew・WinGet） | 初期設定では自分で更新する |

デスクトップアプリとターミナル版は、別々に更新されます。両方使う人は、両方見てください。なお、今日の3つの手口は更新だけでは防げません。更新は土台、設定と使い方が本体です。

## もし漏れたかもしれない時は、この順番

1. 止める：ターミナル版は Esc キー、デスクトップアプリは止めるボタンです
2. 設定を見る：`.claude` フォルダの設定に、覚えのない通信先や許可が増えていないか確かめます。このフォルダは、作業フォルダの中と、自分のユーザーのフォルダの2か所にあります
3. 作り直す：パスワードとAPIキーは、発行元の画面で作り直します。ブラウザーで開いた claude.ai の「設定」→「アカウント」で、全てのデバイスからログアウトします

3つ目のログアウトで、Claude Code もログアウトされます。ただしAPIキーには効きません。キーは別に作り直してください。

## 社長が今日見る6項目

1. ダウンロードのフォルダで起動していないか
2. 仕事ごとのフォルダを、ダウンロードの外に分けているか
3. 許可の一覧に、覚えのない物がないか
4. パスワードやキーをチャットや命令文に直接書いていないか
5. サンドボックスと読み取り禁止を、練習用のフォルダで試したか
6. 最新版になっているか

社内で使う人が複数いるなら、この6項目を月に1回、全員で見るだけでも違います。会社として操作の前に止める仕組みを配る話は、[Claude Code Mods の記事](/blog/claude-code-mods-houjin/)で解説しました。

## 動画の補足：正確にはこうです

1点目。動画では AGENTS.md を Codex のファイルとして説明しました。今は Claude Code も、CLAUDE.md が無ければ AGENTS.md を読みます。確かめる時は、両方の名前を見てください。

2点目。動画では、頼めば許可を求めてくると話しました。今のターミナル版は、初期設定のままだとAIが安全かを判定して進めるため、画面が出ないことが多くなりました。画面が出る前提にしないでください。

3点目。「2回に1回」は、セキュリティ会社が検証用の文面で試した数字です。ふだんの利用で、2回に1回乗っ取られるという意味ではありません。

## よくある質問

### Claude Code は危ないので、使わない方がいいですか

やめる必要はないと考えています。大事なのは、任せる場所と範囲を先に決めることです。練習用のフォルダと、消えても困らない資料から始めてください。

### CLAUDE.md に「パスワードを読まないで」と書けば十分ですか

十分ではありません。それはお願いです。読み取り禁止とサンドボックスを組み合わせて、仕組みの側で止めます。

### 「今後は許可を求めない」は押してはいけませんか

中身を読んで、分かる命令なら使えます。押す前に、保存される文にパスワードやキーが入っていないかを見てください。

### デスクトップアプリだけでも設定できますか

設定ファイルはターミナル版と共通です。保存したフォルダを作業フォルダに選んだ時に読まれます。ただし `/permissions` などの一覧の画面は、ターミナル版で開きます。

### この設定で安全になりますか

被害を小さくする設定です。これだけで全部は防げません。知らない人のフォルダを開かない、鍵を貼らない、更新する。この3つと一緒に使ってください。

## 始め方3ステップ

1. 今日：ダウンロードのフォルダで使うのをやめ、その外に仕事のフォルダを1つ作る
2. 明日：許可の一覧を開き、パスワードと覚えのない許可がないか見る
